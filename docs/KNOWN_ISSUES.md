# 已知限制

更新：2026-10-25。此版本用于开发验收和客户体验。

- 规则不是全部已获客户确认。六款完整 TXT 中的项目拟定项是当前执行版本；四人普通麻将采用四川血战暂定版，包内菜单不构成原服规则证明。红二十缺原模块，部分地方玩法仍需客户核对。
- 原版复刻未完成。茶馆已补审批、模板、成员权限、牌桌、自动开房和战绩，但仍缺消息/邀请、财富操作、大赢家设置、细分权限及完整录像。当前成员统计的大赢家次数不是原版设置功能；馆内列表依赖手动刷新。
- 茶馆最近7天战绩页与公开只读外部 API 已实现，按用户要求 API 无需密钥且不筛除公开战绩；支持日期、成员、玩法和分页筛选，但尚未进行真实公网 HTTPS 验收。微信小程序由外部开发者实现，本项目仅提供接口。任何知道茶馆 ID 的调用方均可读取该馆保留期内的玩家显示名、ID 和战绩。过期战绩立即从查询结果消失，存储清理在启动时及每小时运行；保存失败会留待后续周期重试。接口以房间汇总小局为单位，不提供完整动作回放；每局结算后可查询，不推送实时事件或进行中牌局，`memberId` 根据已保存的房间玩家列表筛选。接口有单进程 IP 请求限流（120次/分钟）和最多16个并发查询；它们用于控制资源占用，不构成访问权限或隐私保护。限流状态不跨实例共享，也不是网络层 DDoS 防护。
- 固定玩法是当前茶馆开桌的前提，原包也有未设玩法时自由创房分支；自动开房采用每模板一空桌，原版具体数量未证实。详见 ORIGINAL_PARITY.md。
- 大厅已按原包功能布局组织，美术和响应式实现为自制；尚未完成原客户端实机画面对照，不能称为大部分或像素级复刻。
- 使用单进程、全局锁和本地 JSON 快照；不支持多实例或多个进程共享数据目录，没有 PostgreSQL/Redis。牌局命令的克隆、规则执行与同步保存仍会串行；极慢磁盘或大型状态仍可能增加动作延迟。后台房间/茶馆维护每秒扫描一次，解散投票到期处理和自动补桌可能有最多约 1 秒调度延迟，尚未压测。保存采用临时文件、同步及重命名，但没有目录 fsync、跨文件事务或进程锁。
- 健康检查表示服务已加载，不主动写盘验证可写性。磁盘、权限、备份与恢复仍需运维监控。
- 100/300/500 连接测试为同账号的多 WS 快照扇出，不能推算同时玩家或游戏吞吐；尚未完成公网、长时间真实对局压测。
- Dockerfile 使用多阶段构建并以非 root 用户运行；Compose 只把 80/443 发布到主机，游戏容器 8080 仅在内部网络暴露。基础镜像目前按标签选择、未锁定 digest；当前环境 Docker Engine 未运行，尚不能实际构建/启动或扫描最终镜像。Caddy TLS、公网域名和实体 Android/iPhone 也未验收。桌面浏览器手机尺寸验证不能替代真机。
- 战绩保留结算、记分账和最近事件，不是整局逐步录像回放。当前牌桌仅支持真人玩家，未实现观战和整局逐步录像回放。
- 安装图标和主屏幕说明已提供，无离线 Service Worker。没有微信 OAuth、短信、真实支付、充值或提现。
- 反向代理需显式配置可信代理 CIDR，且应用端口不得绕过代理暴露；Docker 模板已固定 Caddy 内网地址并配置可信来源。IP 限流仅作用于单进程，部署拓扑、代理头或网络层攻击仍需在实际上线环境验证。
- 账号使用用户名和密码及安全会话 Cookie；当前没有密码重置/找回、短信或微信登录。部署应保护数据目录及管理密钥、启用 HTTPS 和安全 Cookie；发布包不带测试数据。

本实现未使用原私有接口、原代码或原图集音效，因此界面为独立实现，不能宣称原版像素级复刻。
