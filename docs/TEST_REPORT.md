## 2026-10-25 Docker 镜像与调度性能检查

- 静态检查 Dockerfile：前端、Go 构建与 Alpine 运行时分阶段；最终容器使用 UID/GID 10001 非 root 用户，数据目录为 `/data`，8080 健康检查请求 `/readyz`。Compose 只对主机发布 Caddy 的 80/443，游戏服务的 8080 仅在内部网络暴露；未发现将管理密钥写入镜像层的 Dockerfile 指令。
- `node:24-alpine`、`golang:1.27.3-alpine`、`alpine:3.22` 与 `caddy:2-alpine` 使用标签而非镜像 digest 锁定；具体漏洞状态需在镜像成功构建后用可用扫描器检查，重建也可能解析到不同基础镜像。
- `docker compose config --quiet` 配置解析通过。已尝试执行 `docker build --progress=plain -t haojiayuan:codex-check-20261025 .`，但连接 Docker Engine 命名管道失败，未进入 Dockerfile 构建阶段；镜像构建、镜像扫描和容器启动均未完成，不能视为 Docker 验收通过。
- 优化了洗牌：一次读取一批 `crypto/rand` 安全随机字节，并以拒绝采样保持 Fisher-Yates 均匀性，避免每张牌单独请求随机源及创建大整数。自动补桌先单次索引空闲桌，避免每个茶馆玩法重复扫描所有房间；同一玩家的多条 WebSocket 连接复用本次广播的视图 JSON。
- 后台房间维护周期从每 300ms 改为每 1 秒，减少全局锁下反复扫描房间和茶馆模板的频率。解散投票到期处理、自动补桌的响应因此最多增加约 1 秒；该调整尚未通过基准测试验证收益。
- 未改变玩法规则，也未异步化牌局保存。命令处理与本地 JSON 同步持久化仍在单进程串行锁内，慢磁盘时仍可能增加操作延迟。WSL Ubuntu 26.04 / Go 1.26.0 下，本轮改动后执行 `go test ./...`、`go test -race ./...`、`go vet ./...` 均通过；没有现成基准测试，未测量发牌与广播耗时，不宣称卡顿已彻底消除。
- 外部接口由其他开发者接入微信小程序，本项目不实现小程序页面、登录或发布。接口在每局结算后可查询最近7天战绩，响应设置 `Cache-Control: no-store`；不提供推送、WebSocket 战绩订阅或进行中牌局状态，小程序需要按接口契约轮询/刷新。未做微信平台配置或公网 HTTPS 联调。对应缓存头回归断言已由本轮 Go 测试覆盖。
