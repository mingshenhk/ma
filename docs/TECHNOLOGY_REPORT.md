# 技术实现与验收范围

采用 Go 标准HTTP服务和 coder/websocket，React 19.2、TypeScript 5.9、Vite 7.3。开发验证工具链为 Go 1.27.3、Node.js 24.15。服务端可交叉编译 Windows/Linux amd64，不需要原包运行时。

已接入六款规则引擎、同源会话、房间状态机、定时托管、电脑补位、结算、邀请链接、亲友圈、战绩、反馈、管理员状态和Prometheus文本指标。纯规则测试覆盖合法性、终局、计番和零和守恒；服务测试覆盖身份、权限、隐藏信息、幂等、版本冲突、存储失败回滚及重启。

界面使用原创CSS、DOM牌面、图标和Web Audio提示音；支持桌面与手机宽度、横屏提示、全屏入口、规则查看、主屏幕安装说明与manifest。没有导入原图集或音效，没有微信登录SDK、真实支付和离线运行缓存。

本次实际完成100/300/500个WebSocket连接的本机广播测试。500连接接收5500份快照、错误0；10次顺序广播完成耗时p50为4.39ms、p90为4.99ms。该测试是一个账号建立多个连接，不是500名独立玩家同时对局；不能据此推算生产吞吐、网络延迟或服务器规格。完整分档结果见 TEST_REPORT。

当前架构以单进程JSON存储便于交付和复核。生产扩展需引入数据库事务、共享会话/房间路由、消息广播和部署级限流，完成多玩家并发对局及故障测试后再制定容量指标。尚不具备跨实例容灾和完整逐动作录像。

规则证据分为用户明确要求、截图/原包菜单、公开资料与项目拟定。红中计番、红二十/斗十四/跑得快的地方差异按审阅提案实施；新增四人四川血战是暂定开发规则。自动化测试验证当前采用版内部行为，不能证明与未知原服或客户当地规则完全一致。
