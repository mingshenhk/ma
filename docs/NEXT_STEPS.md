# 后续工作

当前六款开发验收版可本地启动，但原版复刻范围仍有缺口。后续先补业务与交互，再做生产部署：

1. 后续玩法调整统一更新六款正式规则、对应实现、规则覆盖矩阵及回归测试；当前不存在等待客户审阅的玩法状态。
2. 按 ORIGINAL_PARITY.md 继续核对并实现茶馆消息/邀请、大赢家设置、细分权限、记录详情等原版流程；财富操作须先明确娱乐积分业务口径。当前固定玩法必选、每玩法补一空桌的行为是项目实现，不伪称原版完全一致。
3. 继续对照原大厅、创房、牌桌、结算的布局和交互；当前只纠正了结构，尚无原客户端实机画面对照验收。
4. 选定部署服务器、域名和备份方式，验证 Docker/Linux 运行、Caddy HTTPS、断网重连以及真实 Android/iPhone 浏览器。上线前以实际对局及目标硬件测量吞吐和长期稳定性。
5. 多进程或多实例部署前替换单写 JSON，实施数据库、并发控制、迁移和备份恢复演练。当前不要多进程共享 DATA_DIR。
6. 短信、离线能力、完整逐步录像回放或更丰富电脑策略尚需实现并验收。微信战绩小程序由外部开发者负责；本项目只维护 API 契约和服务端实现。

7. 公开茶馆战绩 API 按用户要求保持免密和无隐私过滤。上线前需在实际反向代理/域名环境验证可信代理地址、8080隔离、TLS和限流；由小程序开发者配置微信合法域名并完成客户端接入验收。当前限流是单进程内存状态，不适用于多实例或网络层 DDoS 防护。

发布包使用 start.cmd 启动；源码构建、环境变量和生产限制见 README.md 与 DEPLOYMENT.md。

2026-10-25 茶馆战绩外部接入后续：API 已按用户要求开放为无需密钥的只读 GET，支持当天全馆记录和指定成员当天记录。项目只负责接口；接入方配置小程序的 HTTPS 合法请求域名并实现页面。每局结算后可查询，不提供进行中牌局推送。部署后仍需进行真实外部客户端调用验收。当前 API 合同见 EXTERNAL_TEAHOUSE_RECORDS_API.md。
