# 茶馆战绩外部只读 API

更新：2026-10-25。此接口供其他服务（例如由客户或接入方另行开发的微信小程序）读取茶馆战绩；本项目不包含微信小程序，也不负责其登录、页面或发布。

## 权限与密钥

- 每个茶馆使用独立的只读 Bearer 密钥。馆主或管理员在茶馆「设置 → 外部战绩接口」生成、轮换或撤销密钥；普通成员不能管理密钥。
- 密钥生成后只显示一次。服务端只保存密钥哈希，不会在茶馆资料或接口响应中返回密钥。轮换会立即使旧密钥失效，撤销后接口不可再调用。
- 密钥只能读取对应茶馆最近7天内的房间战绩。不要把密钥放在公开仓库、日志或不可信的客户端代码中；正式接入应使用 HTTPS。微信小程序请求域名由接入方在其小程序后台配置。
- 接口启用状态在茶馆成员设置中可见，但密钥值不会向成员公开。该接口不使用登录 Cookie，不要求登录茶馆账号。

## 请求

```http
GET /api/v1/teahouses/{teaHouseId}/records?limit=50&offset=0
Authorization: Bearer hjy_<secret>
```

线上地址与当前服务同源，例如 `https://game.example.com/api/v1/teahouses/{teaHouseId}/records`。开发环境中，页面会显示当前服务地址。跨域 GET 与 `OPTIONS` 预检允许 `Authorization` 请求头。

可选查询参数：

| 参数 | 默认值 | 范围/含义 |
| --- | --- | --- |
| `limit` | `50` | 每页房间数，1–100 |
| `offset` | `0` | 跳过的房间数，0–10000 |
| `game` | 无 | 按房间配置中的游戏 key 精确筛选 |
| `memberId` | 无 | 按当前保存的房间玩家列表中的用户 ID 筛选 |

结果按房间最近一局结算时间从新到旧排列；`total` 是筛选后的房间数，不是小局总数。一个房间结果带有该房间仍在保留期内的全部小局。空房间或没有有效保留期战绩的房间不会出现在结果中。

## 响应

成功时返回 JSON：

```json
{
  "teaHouse": { "id": "club-id", "name": "周末茶馆" },
  "retentionDays": 7,
  "generatedAt": 1792890000,
  "total": 1,
  "limit": 50,
  "offset": 0,
  "records": [
    {
      "room": {
        "id": "room-id",
        "config": { "game": "hongzhong" },
        "status": "finished",
        "players": 2,
        "capacity": 2,
        "round": 4,
        "clubId": "club-id",
        "templateId": "template-id"
      },
      "players": [
        { "userId": "user-1", "name": "玩家甲", "avatar": 1, "ready": false, "total": 12 }
      ],
      "rounds": [
        {
          "number": 4,
          "end": "胡牌",
          "scores": [12, -12],
          "wins": [],
          "ledger": [],
          "at": 1792886400
        }
      ],
      "updated": 1792886400
    }
  ]
}
```

`room.config` 是当前房间配置；`room.status` 为房间状态。玩家字段来自该房间记录。每个小局的 `scores` 为座位顺序的积分结果；`wins` 是玩法结算赢家明细，`ledger` 是转分明细；具体对象字段随游戏规则结算而异。`rounds[].at` 与顶层 `generatedAt`、`updated` 使用 Unix 秒时间戳。响应不包含当前手牌或实时牌局状态。

常见错误：无效/缺失密钥返回 `401`；不支持的方法返回 `405`；分页参数越界或格式错误返回 `400`。错误响应为 `{ "error": "..." }`。

## 保留期限与范围

- 页面与 API 都以 `Round.At` 的 Unix 秒为准筛选最近7天数据；未来时间戳和没有有效结算时间的旧记录不显示。
- 服务启动时清理过期茶馆小局记录，运行中每小时再次清理并保存。清理遇到存储错误会记录错误并在后续周期重试；即使物理清理等待重试，过期数据也不会由页面或 API 返回。
- 茶馆战绩只保留已结算小局及对应的积分/赢家/转分摘要。它不是完整逐步录像，不包含每个摸牌、出牌或响应动作。
- 当前接口部署在游戏服务本身，使用本地 JSON 单写 Repository。它不是独立托管的公共 API 服务；HTTPS、域名和小程序合法请求域名需要在部署及接入时配置。
